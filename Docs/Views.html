Camera Views

A camera view is a component that works out where a camera should be for one frame: its position, rotation, field of view, focus distance and near plane. With a Camera Director in the world, the director asks the active view for its pose, blends it and writes it to its own camera. Without a director, each view writes its pose to its own object (standalone mode). All views share a set of common properties and can carry their own modifier list.

Common view properties

Every view derives from plCameraViewComponent and shows these properties in its View and Modifiers groups.

ModifiersemptyModifiers that only apply while this view is active. They run before the director's modifiers in each stage. See The Modifier Stack.

The subject

Most views have a subject: the object they follow or look at, usually the player. Framing modifiers aim at the subject point, effect modifiers read its speed and ground state, and camera volumes test where it is. Grounded, airborne and crouching states are read from any component on the subject object that exposes the script functions IsStandingOnGround, IsInAir and IsCrouching, which the character controllers do.

Object references

Reference properties such as Target, Spline and EyeObject are picked in the editor like any other object reference. At runtime, a reference set from script is treated as an object path or name, searched relative to the view's object. The Third Person View's TargetObject is always a path or name (default .., the parent).

Looking through a view in the editor

Selecting an object with a view draws its rig in the viewport: a frustum at the view's last pose, plus the view-specific drawing described below. While playing, Cameras.Debug 2 draws the active view's rig.

Third Person View

plThirdPersonViewComponent puts the camera on an arm behind a target. The arm hangs from a pivot point between TargetOffsetLow and TargetOffsetHigh, picked by how far the arm is raised, and pitches between MinUpRotation and MaxUpRotation. A positive up rotation raises the arm, so the camera sits above the target and looks down. The arm is kept below CeilingHeight and above FloorHeight, both measured from the target's origin. A sphere of radius SweepWidth is swept along the arm; when it hits, the camera is pulled in at ZoomInSpeed and lets back out at ZoomOutSpeed, never closer than MinDistance.

Version-1 compatible defaults

With its default settings the view behaves as it did in Game Components 1.x: it follows the target's yaw, pitches only through the RotateUp script function, and its sweep hits static shapes only. Scenes saved with version 1 of the component load their original properties, and every property added in version 2 starts at a value that keeps that behaviour: no look input, Follow Target yaw, no shoulder offset, no lag, no recentering, no dynamic-shape hits and no look-ahead. The common view data loads with its defaults, so FieldOfView 0 leaves the camera's field of view as authored.

The version-2 properties are all opt-in:

  • Look input (LookInput): the view turns from input actions by itself. See Look input.
  • Yaw mode (YawMode): Follow Target keeps the camera behind the target and adds look input as an offset; Free orbits independently of the target's rotation.
  • Shoulder offset and shoulder swap: shift camera and aim point sideways together.
  • Position lag: the aim point trails the target.
  • Auto recenter: swings the camera back behind a moving target after the player stops steering.
  • Hit Dynamic Shapes: dynamic bodies also pull the arm in. Characters never do.
  • Look-ahead: the camera aims ahead of a moving target.

Editor drawing

When the object is selected, the view draws the line between the two target offsets, the arm to the current camera position and its continuation to MaxDistance, the sweep sphere (amber when blocked), the ceiling and floor as squares around the target, and the camera frustum. In edit mode the drawing uses the view's own maths with a level arm, so you can tune distances and offsets without playing.

Setting up a third-person camera

  1. Open the character prefab. Make sure the root has a plInputComponent using the project's input action map if the camera should read look input.
  2. Add a child object named CameraView and add a Third Person View to it. Leave TargetObject at ...
  3. Set TargetOffsetLow to about chest height, for example (0, 0, 1.2), and TargetOffsetHigh to about head height, for example (0, 0, 1.7). Select the object and check the drawn rig.
  4. Set MaxDistance to the arm length you want, for example 3.5, and CollisionLayer to the layer your level geometry uses.
  5. In the Control group, open LookInput and set LookAction to the action that reports mouse or stick movement (or set the four turn and look actions). Set YawMode to Free if the camera should orbit independently of the character's facing.
  6. Optional: set ShoulderOffset to 0.5 for an over-the-shoulder camera, assign a ShoulderSwapAction, and turn on HitDynamicShapes if crates and doors should push the camera in.
  7. In the scene, create a Camera object with a Camera component (Usage Hint Main View) and a Camera Director. Set the director's DefaultView to the CameraView object of the placed character.
  8. Play and turn the camera. Run Cameras.Debug 2 to see the rig while playing.
Note
Without a director, put the Camera component on CameraView instead. The view then moves that object itself, which is how scenes made with Game Components 1.x work.

First Person View

plFirstPersonViewComponent puts the camera at a character's eyes. The position follows the eye object plus EyeOffset. Only the height is smoothed, over EyeHeightSmoothing, so crouching eases while walking stays exact. With YawFromEyeObject on, the yaw comes from the eye object, so a character controller that turns itself also turns the view; pitch comes from look input or script and is clamped to MaxPitch. In a headset (camera mode Stereo) the view adds no pitch, and the director writes only position and yaw, because the headset owns the rest.

The two script functions have the same names and arguments as the Head Bone component's, so scripts written for Head Bone drive the First Person View unchanged.

Setting up a first-person camera on a character with a head object

  1. Open the character prefab. The character controller sits on the root and has a head object as a child (the object it raises and lowers when crouching).
  2. Under the head object, create a child object named FirstPersonView and add a First Person View. Leave EyeObject empty, so it uses the head object.
  3. If the eyes are not at the head object's origin, set EyeOffset.
  4. For pitch, either set LookInput → LookUpAction and LookDownAction (or a vector LookAction), or keep the script that called Head Bone's ChangeVerticalRotation and point it at this component instead. Leave YawFromEyeObject on so the character controller keeps turning the player.
  5. If the player's own arms or weapon clip into nearby walls, set NearPlane, for example to 0.05.
  6. In the scene, set the Camera Director's DefaultView to the FirstPersonView object, or put the Camera component on FirstPersonView for standalone mode.
  7. Add Head Bob, Landing and Recoil modifiers to the director or to the view's own Modifiers list. Head Bob is scoped to first-person views by default.
Note
If the head object still has a Head Bone component, remove it or stop calling it. Both would pitch the camera.

Fixed View

plFixedViewComponent stays where it is placed: a security camera or a fixed-angle shot. Without a target it uses its object's rotation. With a Target it turns to keep looking at it, smoothed by TrackingSmoothing, and sets the focus distance to the target. With FrameTarget on it also narrows the field of view so an area FrameSize meters tall around the target fills the screen height. The result is never below 5° and never wider than FieldOfView, or 90° when FieldOfView is 0.

PropertyDefaultDescription
TargetemptyObject to look at.
TargetOffset(0, 0, 1)World-space offset added to the target's position.
TrackingSmoothing0.15 sTime constant for turning toward the target (0–2 s). 0 turns instantly.
FrameTargetoffNarrows the field of view to frame the target.
FrameSize3Height in meters of the area framed around the target (0.1–100).

Rail View

plRailViewComponent rides along a spline like a camera on a dolly track and looks at a target. The spline is a plSplineComponent; edit its nodes with the Spline Edit Mode. Positions on the spline are evaluated in global space. In Closest To Target mode the camera sits at the point of the spline nearest the target, shifted by KeyOffset. In Scripted mode a script moves it with SetRailKey. Movement along the spline is smoothed by RailSmoothing. Without a target the camera looks along the spline.

Top-Down View

plTopDownViewComponent places the camera high above a target at a fixed pitch, for top-down, isometric and strategy games. The camera looks at the target plus any pan offset from the current zoom distance, at Pitch below the horizon and Yaw around it. Zoom steps, rotation steps and panning come from input actions or script; zoom and rotation changes ease in. With GroundFollow on, the focus point drops onto the static ground under it.

Troubleshooting

SymptomLikely cause
The camera does not move at allThe view has no target (Third Person: TargetObject does not resolve; First Person: no eye object and no parent; Rail: no spline). Or the world has a director that shows a different view.
Look input does nothingNo LookInput actions are set, or no active plInputComponent is found on the subject, its parents, the view's object or its parents.
First-person view does not turn left and right from look inputYawFromEyeObject is on, so yaw comes from the character. Turn the character, or switch the option off.
Third-person camera passes through crates and doorsHitDynamicShapes is off, or the bodies are on a layer that CollisionLayer does not collide with.
The field of view changes when a view becomes activeThat view has a non-zero FieldOfView. Set it to 0 to keep the camera's own field of view.
Camera slides out from close up when play startsThe arm starts short and lengthens at ZoomOutSpeed. Raise ZoomOutSpeed for a faster start.
