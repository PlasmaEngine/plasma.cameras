Gameplay Cameras

The Gameplay Cameras package (plasma.cameras) decides where the game camera is, what it looks at and how it moves. Camera views compute a pose, a camera director picks one view at a time and blends between them, and a modifier stack frames subjects on screen and adds motion such as shake, recoil and head bob. The result is written to the scene's Main View camera.

Concepts

Views

A view is a component that works out a camera pose (position, rotation, field of view, focus distance and near plane) once per frame. It does not move anything by itself when a director is present. The package ships five views:

ViewUse it for
Third Person ViewA camera on an arm behind a character, pulled in by collision.
First Person ViewA camera at a character's eyes, with smoothed eye height and clamped pitch.
Fixed ViewA camera that stays where it is placed and can track and frame a target.
Rail ViewA camera that rides along a spline and looks at a target.
Top-Down ViewA camera high above a target at a fixed pitch, with zoom steps, rotation steps and panning.

The camera director

The Camera Director component sits next to the Main View camera. Views ask to be shown through requests with a priority. The player's own view is always requested at priority 10, camera volumes request at 20 by default, and scripts pick their own priority. The highest priority wins and the newest request wins a tie. Every change of view blends from wherever the camera is at that moment, so a blend that is interrupted by another one never pops. While a sequence cut shows another camera, the director steps aside and blends back when the cut ends.

The modifier stack

Modifiers adjust the pose after the view has computed it and the director has blended it. They live in the Modifiers list of the director (applied to every view) and of each view (applied only while that view is active). They run in two fixed stages:

Viewcomputes a pose
→
Directorpicks the top request, blends
→
Framing stageComposition, Look At, Look Hint, Focus, Lock-On
→
Effects stageShake, FOV Kick, Zoom, Recoil, Head Bob, Lean, Landing, Damping
→
Cameratransform, field of view, focus

Within each stage the active view's modifiers run first, then the director's, each list in order. Framing always runs before effects, so a framing modifier never mistakes shake for subject movement.

Volumes and points of interest

A Camera Volume is a box or sphere that requests a view while the player is inside it. A Camera Point Of Interest marks something worth looking at: when the player presses the Look At key, the camera frames the player and the point together. A Camera Shake Volume Sphere adds shake around a position.

Standalone mode

When a world contains no Camera Director at all, every active view moves its own object instead: it computes its pose, applies its own modifiers and writes the result to its object and to a camera component on that object. A single camera works this way without a director, and so does every scene that used the Third Person View before the director existed. Adding one director to the world switches every view in it to director mode.

Note
In standalone mode a view never writes a focus distance to its camera; only the director does that (see its WriteFocus property). The field of view is written in both modes: a view with FieldOfView 0 (the default) keeps the camera's own field of view, read once when play starts.

Legacy components

The Head Bone and Camera Shake components are kept so existing content keeps working. They appear under Cameras/Legacy in the component menu. New content uses the First Person View and the Shake modifier instead. See Migration from Game Components.

When the cameras update

All cameras of a world update once per frame in the post-transform phase, after objects have moved, and only while the world simulates. In the editor, selecting an object with a view draws its rig; while playing, the Cameras.Debug cvar shows what the director is doing (see Debugging).

Quick start

A third-person camera with blending and shake, in a scene that has a character:

  1. Add the Gameplay Cameras package to the project in the package manager.
  2. Under the character, create a child object named CameraView and add a Third Person View. Its TargetObject defaults to .., which is the parent, so it follows the character. Set TargetOffsetLow and TargetOffsetHigh to points on the character, for example (0, 0, 1.2) and (0, 0, 1.7).
  3. Create an object named Camera with a Camera component whose Usage Hint is Main View, and add a Camera Director to the same object.
  4. Set the director's DefaultView to the CameraView object.
  5. In the director's Modifiers list, add a Shake modifier.
  6. Play. Run Cameras.Debug 1 in the console to see the request stack and the modifiers. A script can call AddTrauma(0.6) on the director to shake the camera.
Note
Without the director (steps 3 and 4), put the Camera component on the CameraView object itself. The view then runs in standalone mode and moves that object.
